a team of specialist bots. Two leads.
The owner approves every gate.

Every feature request or bug report enters through the Captain. Specialist bots work in parallel where it is safe, share one cache instead of re-reading raw documents, and stop at six human approval gates. Click any bot to see what it does.

Two sidesGrok bots vs Cursor sub-agents

🤖 Grok bots

  • Chat teammates with their own memory, in group chats
  • Run on the owner's command, and Captain orchestrates
  • Skills: the shared library (flutter-captain, flutter-clean-feature, flutter-legacy-edit, flutter-responsive-ui, flutter-reusable-widget, flutter-feature-review, <money-feature-module>, coworker-engineer)
  • Store: bot memory (preferences, rules summary) and task files in <AI-ROOT>/<App-Name>/tasks/<TASK-KEY>/

🖱️ Cursor sub-agents

  • Files: <HOME>/.cursor/agents/<prefix>-*.md
  • Started with /<prefix>-captain <TASK-KEY> inside Cursor on the repo
  • Skills: the same skills, copied to <HOME>/.cursor/skills and <REPO>/.cursor/skills
  • Rules: <REPO>/.cursor/rules/*.mdc
  • Store: the same task files

🧩 Which agents, skills and rules are used

  1. The project's own come first: <REPO>/.cursor/agents, skills, rules and AGENTS.md
  2. Ours fill the gaps, combined with the project's
  3. If the project has none, ours are used (global)
  4. On a conflict the project wins, except safety rules (secrets, git by the owner, approvals, test accounts), which always stay ours

Fintech vs TelcoWhat changes in the flow

💸 Fintech (money features)

Transfers, wallet, payments, history

  • Stricter Security: PIN, OTP, amounts, no PII in logs, idempotent requests
  • Extra Gap checks: limits, fees, balances, failure and reversal, duplicate tap
  • QA error flows: timeout mid-payment, insufficient balance, one wrong PIN
  • Test accounts local only
  • Skill: <money-feature-module>
  • Stricter code quality critical issues
  • A failed API in the success flow is a blocker

📶 Telco

Plans, bundles, balance, profile, remote config

  • Focus on backend config and remote config data
  • TTL caching of plans and bundles
  • Local language text
  • Sizer and legacy UI
  • Analytics events
  • Offline and empty states

Shared by both: approval gates, fvm only, light TDD, code quality grade B+ with 80% coverage on changed code, pixel QA against the design, and git done only by the owner.
