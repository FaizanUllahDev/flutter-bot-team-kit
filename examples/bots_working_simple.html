For leadership · How our AI engineering team works

One Captain. Specialist bots.
The owner approves every gate.

The Captain takes every request and hands it to specialist bots, who work in parallel where safe. Work stops at owner approval gates, no bot ever commits code, and all bots share one cache instead of re-reading documents. Click any bot in the map to see what it does.

The flowHandoff chain

  1. Captain reads the request and picks the path (a question gets an answer only)
  2. Intake bots read Jira, the requirements doc, Figma and the code once
  3. The owner approves the brief
  4. Gap Finder lists gaps and questions
  5. The owner answers, and the answers go to the planner
  6. Dev Planner writes the plan, test cases and must-haves
  7. The owner approves the plan and confirms the repo
  8. Devs build and write tests, QA writes test cases
  9. Analyzer gate: fail goes back to devs
  10. Review bots check in parallel, comments go back to devs
  11. QA tests on devices: fail means rework, pass means the report
  12. The owner accepts the QA report, then Jira is updated and Done

Key rulesWhat every bot follows

✅ Quality firstMust-haves before coding, self-check before handoff.
🧪 Light TDDTest cases planned, tests written for every new function.
📊 Code gateGrade B or above, 80%+ coverage on changed code.
🎯 Pixel QAChecked against Figma on several device sizes.
💰 Token savingShort summary files, related files only, failures only.
🧠 Right modelHeavy model only for gaps and planning.
🔄 One rulebookCache Keeper syncs chat bots and Cursor agents.
🧩 Project firstThe project's own rules win, except safety rules.

FAQQuick answers

What if bots disagree?Captain decides, and the owner has the final say.
Faster, but better?Yes: the code gate, pixel QA and loop metrics keep quality up.
What if a bot is wrong?Every stage has an owner gate plus review.
Is data safe?Test data stays local, no secrets are read, and only the owner does git.
