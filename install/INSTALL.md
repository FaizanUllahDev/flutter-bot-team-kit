# Install

The kit has one tool-neutral source (`agents/`, `skills/`, `AGENTS.md`, `.claude/commands/`). `.cursor/` and `.claude/` are committed adapters; every other tool's files are generated by the installer.

## Option A: installer (recommended)
```bash
bash install/install.sh --dry-run   # preview, writes nothing
bash install/install.sh
bash install/install.sh --target=codex,gemini,copilot --git=self   # skip those two questions
bash install/install.sh --tracker=linear --design=figma --docs=confluence --crash=crashlytics --quality=codacy
bash install/install.sh --tracker=other:YouTrack --design=none --dry-run
```
It asks: target (any of cursor, claude, codex, antigravity, gemini, windsurf, copilot, grok, generic, as a comma list, or `both` / `all`), scope (global / project), owner, app, domain, stack, fvm, tracker, design source, docs source, crash tool, code quality tool, who handles git, AI-ROOT, Cursor strong model, and each optional bot.

Git mode: `--git=self` (default, bots never commit, push, rebase or tag) or `--git=bots` (only flutter-dev and git-advisor may run git, after your OK per action; no force-push, `reset --hard` or history rewrites; `.claude/settings.json` keeps `git *` under ask). Repo auth (SSH keys, tokens, GitHub login) always stays with you. The repo source stays in `self` mode; only installed files change.

Tool answers (each has a flag that skips its question):
| Question | Flag | Options | Default |
|---|---|---|---|
| Tracker | `--tracker=` | `jira`, `linear`, `clickup`, `github` (Issues), `azure` (DevOps), `asana`, `other`, `other:<Name>`, `none` | `jira` |
| Design source | `--design=` | `figma`, `penpot`, `sketch`, `zeplin`, `other`, `other:<Name>`, `any`, `none` | `any` |
| Docs source | `--docs=` | `confluence`, `notion`, `google-docs`, `other`, `other:<Name>`, `any`, `none` | `any` |
| Crash tool | `--crash=` | `sentry`, `crashlytics` (Firebase Crashlytics), `other`, `other:<Name>`, `none` | `none` |
| Code quality tool | `--quality=` | `codacy`, `sonarqube`, `deepsource`, `other`, `other:<Name>`, `none` (local rules only) | `none` |

- `other` asks for a name; any unlisted value (for example `--tracker=YouTrack`) counts as a named other tool. Both use the generic rules.
- The answers go into the `Stack:` and `Tools:` lines of the project `AGENTS.md` and `.cursor/rules/team.mdc`. They are names only: the kit adds no integrations, and bots use your AI tool's connector if it has one, or pasted text, files and links.
- `--dry-run` prints a `DRY: tools:` line with the resolved names.

Rules for every target:
- Shared files are written once: `AGENTS.md` and `.agents/skills/` serve every tool that reads them.
- A global single-file rules location that already exists (for example `~/.codex/AGENTS.md`) is never overwritten. The team rules go to `team-AGENTS.md` next to it, and the installer tells you to merge them.
- With `claude` also selected, Grok reuses `.claude/agents/` and `.claude/skills/` instead of writing copies.
- The `/qa-report` command maps to the kit's `qa-report` skill in skill-based tools, so there is never a second skill with that name.
- Git mode (`--git=self|bots`) and the secret / test-account denies apply to every target. Tools with a deny-list file get one: Claude `settings.json`, Codex `.rules`, Gemini policy TOML, Grok `[permission]`. Antigravity, Windsurf and Copilot keep their deny lists in app settings, so the kit relies on the rules in `AGENTS.md` and the approval gates there.

| Tier | Cursor | Claude Code | Antigravity | Codex | Gemini CLI, Copilot, Grok |
|---|---|---|---|---|---|

| strong (gap-finder, dev-planner) | your model name (or `auto`) | `opus` | `pro` | `model_reasoning_effort = "high"` | session model |

## Option B: manual, Cursor
1. Copy `.cursor/agents/*.md` (core + wanted optional) to `~/.cursor/agents/`.
2. Copy each `skills/<group>/<name>/` to `~/.cursor/skills/<name>/`.
3. Copy `.cursor/rules/team.mdc` to `<REPO>/.cursor/rules/`.
4. Replace `<AI-ROOT>`, `<App-Name>`, `<REPO>`, `<TASK-KEY>`.

## Option C: manual, Claude Code
1. Copy `.claude/agents/*.md` to `~/.claude/agents/` or `<REPO>/.claude/agents/`.
2. Copy each `skills/<group>/<name>/` to `~/.claude/skills/<name>/`.
3. Copy `.claude/commands/*.md` to `<REPO>/.claude/commands/`.
4. Copy `AGENTS.md` and `CLAUDE.md` to the repo root (`CLAUDE.md` contains `@AGENTS.md`).
5. Copy `.claude/settings.example.json` to `<REPO>/.claude/settings.json` and adjust.

## Option D: Grok Bot teams
1. Load the `getting-started` skill and answer `install/setup-questions.md`.
2. Load `team-builder` to create one bot per chosen agent file.
3. Give each bot its `agents/*.md` text and `AGENTS.md`.

## Regenerate adapters
After editing `agents/` or `AGENTS.md`:
```bash
bash install/gen-adapters.sh
```

## Uninstall
Delete the copied files. Nothing else is changed.
